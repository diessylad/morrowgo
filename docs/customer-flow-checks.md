# Проверка MORROWGO перед публикацией

Этап: интерфейс покупателя и помощь до выбора поставщика. Реальные eSIM в этой проверке не покупались. `ESIM_GO_FULFILLMENT_ENABLED` должен оставаться `false`.

## Что изменено

- `app/checkout/success/page.js`, `app/checkout/success/layout.js`, `lib/orderPresentation.js`: отдельные состояния оплаты и выдачи, ограниченное обновление статуса, повторная проверка без создания заказа, сумма, копирование номера заказа, пометка тестовой оплаты. Страница заказа исключена из индексации.
- `app/api/orders/status/route.js`: безопасный набор полей для покупателя, признак тестовой оплаты из Stripe, fulfillmentStatus, обработка ошибок и поврежденных записей Redis, сохранение нулевой суммы, запрет кеширования ответа. При объединении с GitHub сохранены customerStatus и установочные данные для оплаченного готового заказа; состояние ошибки имеет приоритет над устаревшим признаком готовности.
- `app/checkout/page.js`, `app/api/stripe/checkout/route.js`: проверка совместимости перед переходом к оплате, явная валюта USD, сообщение после отмены с сохранением выбранного тарифа; внутренние сообщения Stripe не возвращаются клиенту.
- `app/destination/[iso]/page.js`: фильтр минимального срока, сортировка, сброс пустого результата и ссылка на совместимость.
- `app/compatibility/page.js`, `app/compatibility/layout.js`, `app/help/page.js`, `app/customer.module.css`: инструкция проверки телефона, FAQ и информация о подготовке поддержки.
- `app/page.js`, `app/globals.css`: рабочие ссылки помощи, доступ к карточкам клавиатурой, удаление неподключенных элементов рассылки/соцсетей/корзины и неподтвержденных рекламных обещаний.
- `app/demo/order/page.module.css`: мягкие тени карточек и QR в том же стиле.
- `tests/order-status.test.mjs`, `tests/stripe-checkout.test.mjs`: тесты статусов, возврата из checkout и безопасных ответов API.
- `docs/provider-and-competitor-review.md`: сравнение поставщиков/конкурентов и инструкция для почты Network Solutions.
- `docs/customer-flow-checks.md`: эта инструкция.

Stripe webhook и `lib/esimgoFulfillment.js` в этом этапе не изменены.

## Визуальный стиль

По пожеланию владельца сохраняется исходный стиль MORROWGO: чёрный и графитовый фон, белые кнопки, светлый текст, Arial, крупные лёгкие заголовки и скруглённые карточки. Новые разделы продолжают этот дизайн. Карточкам и кнопкам добавлены мягкие тени, тонкий светлый край и спокойное выделение при наведении. Движение отключается при системной настройке уменьшения анимации.

## Выполненные проверки

- `node --test tests/*.test.mjs`: 103 теста после объединения с GitHub, включая 22 прежних проверки webhook. Все внешние запросы подменены.
- `npm run build` (в рабочей среде через `pnpm build`): production-сборка Next.js проходит.
- Локальная production-сборка в отдельном браузере: 1440 × 1000 и 390 × 844. Проверен поиск → страна → фильтр → тариф → подтверждение совместимости → переход к странице заказа. Весь каталог, Stripe и статусы подменены; внешние запросы заблокированы.
- Проверены ожидание eSIM, неуспешная проверка, готовность, неизвестное состояние, неподтвержденный платеж, неправильная ссылка, повторная проверка статуса, отмена checkout, checklist совместимости, раскрытие FAQ и демо-установка. Нет горизонтального переполнения проверенных страниц и JavaScript-ошибок.

Это проверка интерфейса и серверной логики на тестовых данных. Она не подтверждает связь eSIM в сети оператора и не заменяет проверку нового деплоя Vercel.

## После Commit и Push в GitHub Desktop

1. В Vercel открыть новый deployment и дождаться **Ready**. Сверить commit с отправленным изменением.
2. Открыть `/api/esimgo/fulfillment-health`: ожидается `moduleReady: true`, `fulfillmentEnabled: false`.
3. Открыть `/help`, `/compatibility`, `/demo/order`. В FAQ раскрыть вопрос; в совместимости отметить три пункта; в демо переключить состояния и инструкции.
4. На `/destination/DE` изменить минимальный срок и сортировку. Выбрать тариф: на checkout кнопка оплаты доступна после подтверждения совместимости.
5. Открыть исходную ссылку уже существующего тестового заказа. Проверить корректный статус, сумму, копирование номера и кнопку повторной проверки. Для этого не нужен новый платеж или повторная отправка webhook.
6. Проверку нового Stripe checkout проводить только в подтвержденном тестовом режиме. Отмена должна возвращать к выбранной стране и тарифу. `200 OK` от webhook означает прием события; готовность eSIM определяется статусом заказа.
