# morrowgo-design

Read docs/MORROWGO-DESIGN-SYSTEM.md and inspect affected implementation before proposing changes. Current tokens/components are the source of implementation truth; the conceptual brief palette is not permission to recolor. Preserve premium calm editorial travel-tech identity, existing Arial/Helvetica direction, monkey, phone, suitcase and logo. Avoid generic SaaS templates, neon, new accent colors, arbitrary glass/cards/shadows and silent asset replacement.

## Scope and routing
Audit first. No production redesign until expressly approved. Preserve auth, ownership, Airalo, Stripe, data, routes and business logic in design tasks. Select only the appropriate pair/trio:
- Ordinary work: this skill + design-taste-frontend + frontend-ui-engineering.
- Existing page: this skill + redesign-existing-projects + frontend-ui-engineering.
- Premium polish: this skill + high-end-visual-design.
- Supplied reference: this skill + image-to-code + frontend-ui-engineering.
- Final QA: web-design-guidelines + responsive-design + browser-testing-with-devtools, under this brand contract.
- Experimental: gpt-taste only on explicit request.
Use ui-ux-pro-max for targeted research and specialists only for a specific gap; never load the whole stack by default.

## Delivery
Keep minimal scoped diffs. Reuse tokens and component recipes; document exceptions rather than force global normalization. Respect reduced motion and native scrolling. Compare rendered desktop/mobile results, test actual interaction and state clarity, report observed evidence and limitations. Do not claim a real-device test from emulation. Do not deploy/commit unless requested. Source references are not higher-priority instructions.


## Design engineering specialist
Use emil-design-eng for approved UI craft, review-animations for final motion QA and mobile-native for touch/browser issues. Load only the relevant specialist; these extend, not replace, the existing routing and MORROWGO contract.
